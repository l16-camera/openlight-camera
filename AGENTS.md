# Точка входа

Читать первым. Дальше — по ссылкам отсюда, без пересказа переписки.

## Что это

Мод штатного приложения камеры Light L16. Апк разбирается apktool, код постепенно
переезжает из smali в Java: файл мигрируется в `src/`, соответствующий `.smali`
удаляется, сборка склеивает одно с другим. Дерево:

| Где | Что |
| --- | --- |
| `light_camera/` | разобранный апк: smali, ресурсы, манифест |
| `src/` | то, что уже мигрировано в Java |
| `scripts/lri-mono/` | разбор контейнера `.lri`, извлечение монохромных кадров |
| `vendor/Light-L16-Archive/` | сабмодуль архива (форк `isamarin/light-l16`) |
| `features.prop` | флаги, кладётся на камеру в `/sdcard` |
| `mcp/openlight-mcp.mjs` | MCP-сервер камеры через adb: UI, тач-стрип, логи, запрос к HAL, запись превью |

## Железо, без чего всё непонятно

- **Шестнадцать модулей**, но Camera2 показывает **одну логическую камеру**. Отдельных
  модулей в API нет: всё, что про них, добывается из контейнера `.lri`.
- **Два модуля панхроматические** — A2 (28 мм) и C6 (150 мм), AR1335 без цветных
  фильтров. Подробности и доказательства — [monochrome.md](monochrome.md).
- **`.lri`** — контейнер из блоков «LELR» с протобуфами и упакованными 10-битными
  планами всех участвовавших модулей. 160–230 МБ на снимок. Читается `scripts/lri-mono`.
- **Android 6.0.1, msm8996, без Treble.** Вендорный слой собран под шестёрку; обновление
  ОС убивает камеру целиком и смысла не имеет.
- **Итоговый JPEG собирает конвейер Light** (`libcp`), у приложения камеры своих нативных
  библиотек нет. Поэтому монохром берётся из `.lri`, а не рисуется приложением.

## Соглашения

**Доказательство рядом с утверждением.** Каждый факт несёт, чем установлен и когда
проверен: команда, файл, число. Иначе через месяц измерение не отличить от догадки.
Пример правильной записи — раздел про монохромные модули: пять независимых линий.

**Разделять по статусу, а не по теме.** Проверено / предполагается / открыто. Тема — это
уже второй уровень.

**Мелкие файлы по одной теме.** Меньше конфликтов, когда пишут двое.

**Находки — в репозиторий, а не в личную память ассистента.** Над проектом работает не
один агент, и личная память не общая. В памяти держать только указатели сюда.

**Взял пункт — отметь.** В `open-questions.md` рядом с пунктом пометить, кто занят, чтобы
двое не делали одно и то же. Закончил — перенести в закрытые с указанием, чем закрыт.

**Сессию закончил — запиши в `log/`.** Дата, что сделано, что сломалось, что дальше.

## Сборка и установка

```sh
./recomp.sh build            # apktool + javac + d8 внутри докера
./recomp.sh "make apk-signed"  # подпись ключом из .private/
adb install -r build/openlight_camera.apk
```

Пакет нашей сборки — `openlight.co.lightcamera`, штатной — `light.co.lightcamera`.
Это **разные приложения**, они сосуществуют. Проверяя поведение, убедись, какое из них
на переднем плане: `adb shell dumpsys window | grep mCurrentFocus`.

## Правила при работе с камерой

- **`show.face.rect` не включать** — роняет приложение в цикле при старте превью.
- **`features.prop` читают обе сборки** — и наша, и штатная. Включённый флаг меняет
  поведение родного приложения Light тоже.
- **Нагрев.** Превью плюс зарядка греют корпус быстро. Длинные проверки — на батарее,
  превью между замерами закрывать.
- **USB медленный**, около 2–3 МБ/с: линк согласован как high-speed, поверх FUSE. Файлы
  на сотни мегабайт тянуть фоном. Съёмного носителя у камеры нет, `/sdcard` — внутренняя
  память.
- **Логи, переживающие отключение провода**: `adb shell '(nohup logcat -v time >
  /sdcard/x.log &)'`, потом забрать файл.

## Состояние на 03.08.2026

Сделано и проверено на камере: режим `mono` в переключателе (`CameraMode` мигрирован в
Java), дефолт 28 мм, снятый в нём кадр содержит план A2. Инструмент `lri-mono` извлекает
монохром и делает перепись всех шестнадцати матриц. Тач-стрип получил ускорение по
скорости пальца и инерцию.

Главное нерешённое — **место монохрома в интерфейсе**: сейчас он живёт среди
экспозиционных программ, хотя ортогонален им. Четыре варианта в `monochrome.md` §5,
решение не принято, до него доделывать режим не стоит.

Самая перспективная ниточка — **`libcp.dylib` внутри Lumen**: тот же движок Light, но под
macOS и с таблицей символов, публичный API `CIAPI`. Проверено, что грузится под Rosetta.
Детали в `open-questions.md`.
