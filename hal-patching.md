# Патч HAL и драйвера камеры

Можно ли переделать то, что Camera2 не даёт: выбрать состав модулей для снимка и снимать
видео больше чем с одного модуля. Ответ — да для HAL при условии root, и почти наверняка
нет для драйвера. Ниже: что проверено, что предполагается, что открыто.

## Проверено

**Что мешает изменить снаружи.** Камера LFCLHMB7C0700105, LightOS 1.3.5.1, чтение по adb
2026-10-15 (`getprop`, `mount`, `id`):

| | значение |
| --- | --- |
| сборка | `ro.build.type=user`, `ro.secure=1`, `ro.debuggable=0` |
| root | нет: shell `uid=2000`, `su` недоступен |
| verified boot | `ro.boot.verifiedbootstate=green`, `ro.boot.veritymode=enforcing` |
| `/system` | `/dev/block/dm-0`, ext4, `ro` — под dm-verity |
| ядро | `3.18.20-perf-g32d1d1c`, сборка 21.11.2019, `/proc/config.gz` есть |

**Где сидит состав модулей.** `camera.msm8996.so` (ARM32, с камеры
`/system/lib/hw/`), функция `qcamera::translateLightCaptureIntent` @ 0x5ee2c. Маска
`capture_mask` приходит третьим аргументом из `translateToHalMetadata`, который читает её из
поля `QCamera3HardwareInterface + 0x50`. В это поле пишет только конструктор — из запроса
Camera2 её не выставить. Байт `+0x54` (в логе HAL подписан `burst_count`) устроен так же;
если он больше 1, HAL берёт его вместо числа кадров из таблицы intent — вторая ручка того
же патча.
Подробности и таблица intent → число кадров — `log/2026-10-15.md`.

**Где сидит видео.** В ядре один сенсор: `v4l-subdev17: i2c_camera 11-0010`, один
`msm-sensor`; рядом 3 CSIPHY, 4 CSID, 2 VFE. Видео — центрированный кроп модуля A1
(`log/2026-10-15.md`, «Видео идёт с модуля A1»).

## Предполагается

- **Патч HAL небольшой.** Достаточно, чтобы `+0x50` бралось не из конструктора, а например
  из `property_get` или из вендорного тега: несколько инструкций в
  `translateToHalMetadata` или в конструкторе. Значение маски дальше уже уходит в CCB
  (`[LIGHT] issue ccb cmd … capture mask`). Что маска значит побитно — неизвестно, но
  гипотеза «бит на модуль» проверяется перебором.
- **Путь к подмене библиотеки — systemless.** Писать в `/system` нельзя из-за verity;
  Magisk кладёт изменённый файл поверх, не трогая раздел. Для этого нужен разблокированный
  загрузчик и пропатченный boot.
- **Root на L16 сообщество получало.** В README архива совет снимать root перед
  обновлением до 1.3.5.1. Каким способом — не выяснено.
- **Оценка:** управляемая маска модулей при открывающемся загрузчике — около 60 %.

## Открыто

- [ ] **Разблокируется ли загрузчик.** Проверка без потери данных, но с перезагрузкой:
      `adb reboot bootloader`, `fastboot oem device-info`, `fastboot reboot`.
      Сама разблокировка обычно стирает `/data`.
- [ ] **Чем рутовали L16** — найти тред на XDA, версию Magisk/SuperSU под Android 6.
- [ ] **Исходники ядра FIH для LFC (3.18).** Без них правка драйвера сенсора почти нереальна.
- [ ] **Умеет ли ASIC стримить два модуля сразу.** Главное неизвестное для видео. Даже с
      драйвером на два потока ответ даёт только прошивка ASIC, а она закрыта.
- [ ] Оценка для видео с нескольких модулей — около 10 %; пересмотреть после двух пунктов
      выше.

## Порядок и риски

1. Опыты вести на **втором корпусе**: ошибка в boot может превратить камеру в кирпич, а
   разблокировка стирает данные. С этого корпуса весь DCIM уже снят (BLMKGO, 2026-10-15).
2. Проверить загрузчик → найти способ root → снять полный дамп разделов до любых правок.
3. Патч HAL через overlay, перебор `capture_mask` по одному биту, проверка состава
   модулей в `.lri` (`light gather`).
4. Драйвер — только если появятся исходники ядра.
